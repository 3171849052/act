# 执行记录

所有项目原始训练、模型、环境代码均保持原样。训练调用官方 main()/train_bc()，包装器只记录数据划分和真实损失指标、关闭已保存的绘图对象，未调整优化、预测或动作逻辑。

首次用 shell 后台启动时，启动终端退出导致调度器未能持续运行；其已脱离进程组的 ACT 两轮测试工作进程完成，并留下完整日志、检查点、曲线和指标。随后重读并校验这些真实产物，记录为已恢复的短测试，耗时明确标记为文件时间戳差值。没有将该模型当作正式模型，也没有重复正式训练。

调度器改用 Python subprocess.Popen(start_new_session=True, close_fds=True, stdin=DEVNULL) 脱离启动终端。当前 PID 由 pipeline.pid/launcher.pid 记录，实际进程 PPID=1，已在启动会话结束后确认继续推进 CNNMLP 短测试、50 轮测速及三模型正式训练。

追加的项目源码 SHA256 快照记录于正式训练启动后，时间与来源明确保存在 source_snapshot.json；项目源码与初始工作区一致。后续启动的模型/评估工作进程同时在配置中记录源码哈希。最终检查将再次校验源码与数据未变。

pipeline_validation.json 记录了两项执行前验证：评估源码 AST 仅改变回合数和视频保存条件；正式模型未完成时，完成检查拒绝创建 finish.txt。这是有意验证完成门槛，未改变后台实验状态。
